# 命令行操作详解（1.9.1）

这份说明供批量操作、开发或排查时使用。**普通使用者通过 `app.py` 的界面操作即可，不需要把下面的命令全部运行一次。**

## 先看懂命令在哪里执行

以下命令在 **PowerShell** 中、项目根目录下执行。根目录就是直接包含 `app.py`、`cli.py` 和 `README.md` 的文件夹。以下假设项目在这个位置，实际不同就修改：

```powershell
Set-Location "D:\Projects\anti-telecom-fraud-model"
```

执行前先完成 [README 的环境安装](../README.md#install-new)。一次复制一条，回车后等结束再做下一步，不输入到 Python 的 `>>>` 后面。

命令一般分三部分：

- `.\.venv\Scripts\python.exe`：使用当前项目自己的 Python。
- `cli.py`：使用命令行入口。
- 操作名和参数：告诉程序要做什么、用哪个数据集和案件。

`--dataset` 后是已整理好的数据目录，`--case` 后是其中已有的案件编号。下面的 `C001` 来自合成样例，更换数据集后不能随意照填。

**案件文本批次与结构化流水数据集是两种格式。** 下面以 `data/enhanced_sample` 为例的命令使用结构化合成数据，不会自动分析“案件文本研判”中刚导入的工作簿。

## 1. 检查环境和随包文件

```powershell
.\.venv\Scripts\python.exe cli.py preflight
```

**用途：** 检查配套库、当前资金/人员/联合模型文件及默认数据快照等。默认数据目录是 `data/enhanced_sample`。

**怎么看：** `checks` 是清单，`status` 是状态，`detail` 是详情。`"ready": true` 表示本轮软件和文件检查通过；`false` 时看具体缺失或失败项。

它不评估真实准确率，也不检查全部媒体权重，不能代替实际录音转写检查。不会训练模型。

## 2. 跑完整的结构化演示流程

```powershell
.\.venv\Scripts\python.exe cli.py workflow --dataset data/enhanced_sample --case C001
```

**用途：** 对合成 C001 执行来源检查、金额统计、模式、IP/产业关联、适配模型和报告等步骤。这里的全流程不表示自动清洗任意 Excel，数据需先符合系统结构。

**怎么看：** 终端显示进度，结束后 `output` 是实际目录，`status` 为 `complete` 表示流程完成。失败时看错误和本次 `run.json`，不把历史报告当成本次结果。

**结果位置：** 默认在 `runtime/analysis_runs` 下，打开本次目录的 `index.html`。

会新建报告和本机记录，不重新训练或替换模型。合成结果只验证流程。

## 3. 只看统计和模式提示

```powershell
.\.venv\Scripts\python.exe cli.py analyze --dataset data/enhanced_sample --case C001
```

**用途：** 查看图中主体/关系数量、分币种金额及模式提示。

**怎么看：** 结果显示在终端。`nodes` 是节点数，`edges` 是关系数，`amounts` 是金额，`findings` 是模式提示。`paths` 是额外指定起终点时的路径，未指定时可以为空。

这条命令不导出整套网页报告，也不训练模型。不同币种不能混加，提示仍需核验。

## 4. 导出结构化分析报告

```powershell
.\.venv\Scripts\python.exe cli.py export --dataset data/enhanced_sample --case C001
```

**用途：** 导出当前案件的网页、图谱、统计、适用时的模型候选与核验信息。

**结果位置：** 终端打印输出目录，默认在 `exports` 内。打开本次目录的 `report.html`，旁边有对应 ZIP 用于整包保存。

会生成文件，不训练模型。更换数据目录和案件编号时须保证对应；真实数据需要适配模型，自带合成模型不为真实案件评分。

## 5. 查看合成人员角色和层级候选

```powershell
.\.venv\Scripts\python.exe cli.py roles-predict --dataset data/enhanced_sample --case C001
```

**用途：** 用已选人员模型计算候选。“预测”是使用已有模型，不是训练。

**怎么看：** 终端显示可用状态、候选和说明；不可用时看 `reason`，即原因。层级与连线不是已核实控制关系。

不会修改模型；需要网页结果可使用第 4 节导出。

## 6. 可选：重新训练合成人员模型

**会产生新模型，并将“当前人员模型”切换为新训练版本。只想使用系统就跳过，不是每次启动前的必做操作。**

```powershell
.\.venv\Scripts\python.exe cli.py roles-train --dataset data/role_training_synthetic --epochs 100
```

**用途：** 在专门的合成人员训练集上训练角色与层级模型。

`--epochs 100` 指最多 100 轮训练，不是 100 个案件，也不是达到 100% 准确率。程序按训练/验证规则选择模型并打印指标。

**结果位置：** `runtime/models` 中新建时间命名目录，同时更新 `roles_latest.json` 的版本引用。旧版本目录保留，界面“实证与运维 → 模型版本”可查看符合校验条件的版本。

它仍是合成训练。真实训练需核实标签、任务定义、独立关联组和独立评测，不能只把三个案件说明表的路径换进来。

## 7. 运行准备好的合成因果研究

```powershell
.\.venv\Scripts\python.exe cli.py causal --input data/causal_demo
```

**用途：** 读取专门研究表格和配置，在声明条件下执行调整、诊断与稳健性检查。

**怎么看：** `available` 表示能否估计，输出还包含可用时的估计值、区间、范围说明和 `output`。打开本次目录的 `report.html`，默认在 `runtime/causal_runs`。

“不可用”可能说明研究条件不满足，不能强行解释数值。这是群体层面的条件性研究，不证明个人犯罪因果；不会替换人员模型。

## 8. 把演示录音转为文字

先按 [README 语音模型准备](../README.md#speech-model)完成下载，再执行：

```powershell
.\.venv\Scripts\python.exe cli.py extract --input data/media_demo/synthetic_speech.wav --origin synthetic
```

**用途：** 读取合成录音，提取文字和待核对字段。`--input` 是文件路径，`--origin synthetic` 标记虚构来源。

**怎么看：** `output` 为输出目录，`segments` 是片段数，`candidates` 是候选数，`notes` 是提示。默认在 `runtime/extractions`，没有识别到内容时不能凭空补通信。

自己的录音改用实际路径，路径有空格时加双引号，真实来源用 `--origin real`。普通使用者建议走界面的“原始材料识别”，便于修订文字、核对主体和时间。识别不自动生成已核实交易或身份绑定。

## 9. 开发检查：运行自动化测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

**用途：** 发现并运行 `tests` 中的程序测试。这里没有 `cli.py`，因为调用的是 Python 自带测试工具。

**怎么看：** 结束后显示本次实际测试数量，全通过时最后为 `OK`；出现 `FAIL` 或 `ERROR` 则看对应错误。不能用旧文档的计数冒充本次结果。

普通导入、查看和导出不用每天跑整套测试。测试通过只说明覆盖范围内的程序行为正常，不等于真实侦查准确率通过验证。

## 遇到问题怎样反馈

记录：执行的整条命令、当前项目路径、完整错误文字、数据格式与来源。涉及真实资料时，不把原件或含个人信息的输出发到公开仓库。
