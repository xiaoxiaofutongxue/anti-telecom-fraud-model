# 1.6 案件文本四流研判

本版按用户提供的三份“四流分析、时空联动与产业回流”工作簿增加文书型资料入口。它们直接作为原始资料输入，不要求先改成逐笔流水，也不要求补造训练标签。

当前使用本地表结构识别、文本提取规则、提及关联图和 TF-IDF 资料检索。三个样本用于接入和解析验证，未据此训练分类器，未给出真实识别准确率或跨案件泛化结论。

## 怎么启动与导入

双击项目根目录“启动系统.vbs”，或在 PyCharm 使用项目 `.venv` 解释器运行 `app.py`。改动后的程序需要正常关闭旧窗口再启动。项目仍在 `D:\Projects\FourFlowAnalysis`。

1. 点击顶部“案件文本导入”，或左侧“案件文本研判 → 导入案件文本并研判”。
2. 一次选择三份原始 XLSX，或其他同类工作簿、DOCX、TXT、MD。无需逐工作表导入，无需删除标题行和手工修改表头。
3. 等待完成，在“当前资料”下拉框切换三个资料。
4. 查看“四流研判摘要”“资料检索与原行”“主体与资产提及”“金额与时间口径”。
5. 点击“打开报告目录”，打开 `index.html`。报告包含表内资金/回流路径、跨流会合提及、来源关联图、时间线、金额口径及核验清单，另有原件、CSV/JSON 和 ZIP。

以后可继续导入同类资料，也可点“粘贴案件文本”，填写资料名称并粘贴正文，保存后自动研判。粘贴内容作为新的原文文件保留，不执行其中指令。

本入口与“CSV/Excel接入”的逐笔流水入口独立。顶部“流水案件”和截至时间只在原有结构化分析页面显示；文本资料在本页选择。文本页点击顶部“导出分析报告”也会导出文本报告，避免误导出其他流水案件。

## 输出怎么看

| 输出 | 含义与查看方法 |
| --- | --- |
| 四流资料行 | 按工作表与原文标签归类；同一行可涉及多流，计数不能相加为独立事件数 |
| 资金/产业回流路径 | 保留原表明确写出的路径陈述和段落定位；不是系统验证了同一笔资金或控制方向 |
| 跨流会合提及 | 同一资料内，同一主体称谓或资产文本在不同流别出现，提示交叉核验；不是独立来源印证 |
| 主体/资产提及图 | 主体、机构、钱包、域名、原文坐标与资料行之间的提及联系；同名跨案件不自动合并 |
| 原文时间线 | 按明示日期/区间排序；年/月区间保留精度，持续/同期等未知时间不补日期，省略的区间末端保持未知 |
| 金额/数量 | 数字、币种、约数限定与余额/汇总/费用/行业统计分类展示，不加总为案件交易额 |
| 钱包前缀 | 截短地址独立保留，不自动绑定到完整钱包；未调用链上接口获取或推定交易 |
| 核验清单 | 缺文书定位、粗粒度时间、金额重叠、钱包不完整等具体问题，均能返回原行 |

表中角色层级、实际功能和核心结论保留为来源中的分析或陈述，不自动变为事实、控制关系或监督标签。地点和坐标不被转换成 IP 访问日志，域名也不被自动认定为违法网站。

## 检索和人工核验

在“资料检索与原行”输入“资金回流”“园区迁移”“USDT”“手机”等关键词，点击“检索本批资料”。结果可来自本批三个资料，按文字相似度排列，不代表事实正确率。

点击结果，查看文件、工作表、行号、原文和文书段落；“打开原件”可在本地打开对应文件。结果若来自另一份资料，核验会正确保存到该资料，而不是当前下拉框所选资料。

填写核验人和依据，选择待核验、已核实线索、已排除或待补充材料，点击“保存本条核验”。被排除的行保留在来源索引与核验记录中，但不再用于提及图、金额提及及路径摘要。排除后需“更新并导出报告”，历史报告保持原版本。

保存核验或更新报告后会保留当前检索结果和选中原行；重新选择其他行时清空旧表单并回读该行的核验记录。重启后资料会恢复，当前报告需点击“更新并导出报告”重新生成。

人工核验并不自动把不完整文本变成金融流水。资料里的日期、金额或主体不足时，保留原意和未知项。

## 文件、恢复和接入限制

- 原件副本与解析记录保存于 `data/narrative`，当前引用为 `runtime/narrative_latest.json`，重启可重新校验并载入。
- 报告在 `runtime/narrative_runs`。报告 ZIP 包含本批原件和原行定位，是私有文件；无需联网，未上传第三方。
- 源副本被替换、解析文件被改或来源引用越界会拒绝载入；原件 SHA256 和位置用于一致性复核，不证明文书陈述真实。
- 文本报告目录本身可作为“打开已接入资料”的来源目录，因为包含清单、解析记录和原件。
- “实证与运维 → 备份与恢复”现包含当前案件文本资料和引用，并保留核验数据库。其他历史批次和所有历史报告仍需按需另行保管。
- 支持 XLSX、DOCX、TXT、MD，单文件50MB、工作表200列/50000行、每文件最多10000条内容、每批最多30文件/50000条内容；超限明确停止，不静默截断。上述为输入防护上限，不是已完成同等规模压力测试。
- XLSX 公式不执行，也不将公式行提取为金额或资产事实。DOCX 保留段落/表格行位置，不编造原版页码。TXT/MD 支持 UTF-8/GB18030。

## 本轮验证

三份用户原始工作簿的内容指纹与此前一致：共30张工作表、597条内容行、55条表内资金/产业回流路径。读取结果包括25个完整BTC钱包文本、截短钱包和原文坐标；未补造IP访问或交易。

实际样本验收21项通过，包含原件不变、全部工作表接入、原行定位、存量/统计口径区分、未知时间、路径保留、来源检索、报告文件与链接、ZIP、旧模型引用/权重不变及审计一致性。完整核验记录在 `runtime/upgrade_1_6/acceptance_result.json`。这验证解析与工程流程，不表示原始文书真实性、法律事实或训练模型性能通过。

原有监督模型、因果研究、材料识别及逐笔图谱继续保留。旧版文档是历史记录；本入口以上述流程为准。
