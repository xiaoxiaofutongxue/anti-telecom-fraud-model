# 原文核验与材料符合性 1.7

本轮改进文书数据的提取与核验，并逐项核对《模型大纲》和《第一章 执行摘要》的技术要求。当前能支持有来源的辅助研判；原材料中的真实分类、层级恢复、因果证明和泛化目标仍需要独立证据与经核实的评测数据，不能据三个案件摘要宣布全部达标。

## 本轮改进

修复多段表头切换后的金额币种丢失；支持明示美元表头下的多项数字、共享币种后缀表达式和负值。金额区间、未明币种、约数、存量、费用和背景统计分别保留；每项带字段、单元格、原文片段与单位依据，不计算叙述数字的交易总额。设备型号不作为金额，科学计数等未完整支持的写法保留并提示。

补充带N/E等方位标记的小数坐标、掩码钱包、t.me域名与明示别名；短中文称谓可参加原文提及匹配，CC-1不匹配CC-10。同名跨案仍隔离，别名有歧义时不扩展联系。BTC Base58Check编码检查独立于地址归属、链上活动和事实核实；校验失败保留原文，不静默纠错。规则参考[Bitcoin Core Base58实现](https://github.com/bitcoin/bitcoin/blob/master/src/base58.cpp)与[BIP173对既有地址格式的说明](https://github.com/bitcoin/bips/blob/master/bip-0173.mediawiki)。

对于省略年份/月日、混合分隔符、多日期列举、至少/持续等开放区间，保留不确定性。工作表来源说明中的引注与逐行直接引注明确区分。原件和历史解析批次保留，新规则通过重新导入产生新批次；历史核验意见不自动迁移为新版本已核实记录。

| 调证线索清单 | 待取得材料、目的、处理顺序、原行位置和核验状态；CSV导出 | 清单供人员审查使用，不自动发出调证或代替正式手续 |

桌面新增“需求输出与核验”页；每个案件均显示上述八项状态、相关原行数量及具体待补项。HTML报告包含原文角色表、路径图和核验清单；CSV新增investigation_checklist和path_segments，JSON保留完整节点、边及来源。

## 怎样理解本轮指标

在修改提取规则前，固定了46项原文转录对照检查，覆盖37个明示金额值、6处坐标、5个掩码片段、域名、表头、流别、引注和时间边界。修改前24项通过，修改后46项通过；该清单是已阅样本的开发回归，不能表示任意文书准确率、外部留出效果或真实电诈识别率。

三个工作簿的新解析含595条内容行；与1.6的597条相比，两行已正确识别为表头并保留在结构记录中，没有删除正文或修改原件。文书中的同一金额可能在多张表重复出现，新增提取项数量不能理解为新增交易数或案件规模。

“narrative-audit”接口可对照独立复核的清单计算字段提取的TP/FP/FN，绑定原件SHA256，来源变化时拒绝复用旧答案。此接口始终不产生诈骗或团伙分类准确率；该项仍须使用独立核实的案件标签和符合任务定义的外部留出数据。

本轮源文对照、外部公开文书抽查、错误清单及交付记录保存在本机runtime/upgrade_1_7，属于私有验证资料，不进入通用软件包。公开文书中的指控/宣誓陈述与已裁判事实也分别对待。
