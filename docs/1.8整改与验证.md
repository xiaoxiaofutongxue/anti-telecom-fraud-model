# 1.8 整改与验证

本轮补齐文书输入的结构还原、明细核算和结构化数据的特征/示例公式核验。真实分类器权重没有重训，没有将三个已阅案件的结论变成监督答案。

## 操作

在 PyCharm 打开本项目，使用项目的 `.venv` 解释器运行 `app.py`。也可双击项目中的“启动系统.vbs”。工作数据和输出均保存在项目所在 D 盘。

1. 进入“案件文本研判”，导入 XLSX/DOCX/TXT/MD，或选择已接入的资料。
2. “需求输出与核验”展示大纲八项输出的当前条件。“结构还原与核算”展示来源隔离、关系方向候选、列示项目核算、支付明细、日期对应依据和证据缺口。
3. 在“资料检索与原行”核对原件，填写核验人和依据。排除记录后重新计算，排除项不再贡献关系和金额。来源行的核验不自动成为模型训练标签或现实控制关系。
4. 点击“更新并导出报告”。报告包含关系局部层次图、原文路径图、逐项原行链接，以及 `statement_payments.csv`、`hierarchy_candidates.csv`、`amount_reconstruction.csv` 和完整 `result.json`。历史报告保留原版本。
5. 有真实逐笔结构化数据时，在“IP与产业溯源”点击“特征与公式核验”。此页使用顶部的流水案件及截至时间，与文书案件选择独立；不能把合成示例的特征当作已导入文书的结果。

## 关键处理

匿名编号在案件和文书范围内使用。只有原文明确说明同一文书时才合并来源编号；该声明仍待核验。混合来源不自动建立上下级，缺失出处在存在多个来源时按原行隔离。地域前缀加匿名编号不拆成地点别名，避免把园区提及连成人物。

只从明确的付款方、收款引用及金额字段还原明细，不把余额、汇总、费用或背景统计拆成支付。并列日期与金额只有数量相同且不是区间/约数时才按原文顺序对应，并记录省略的年/月；这是待核验的对应假设。区间中的多项金额保留共同区间，不编造各笔日期。掩码钱包及复合收款方保持原文，不补齐或任意分配。

金额按来源与币种使用 Decimal 精确计算列示名义合计，并分银行支付和加密资产法币等值。相同付款引用、收款引用、日期及金额元组仅标记可能重复。条件区间的下界每组可能重复项目计一次，上界列示项目全部计入；前提是不同元组确实代表不同支付。负数、约数或混合出处阻止该条件区间。没有覆盖率和本金同一性证据时，全案损失、全案上界均保持未知。条件区间不是统计置信区间。

上下级候选只来自明示的汇报、直属或指令语句，保留方向、原文、来源及循环检查。未连接的人不因“总头目”等称谓被强制置顶；存在循环时不强制分层。否定及未证实表述不生成正向关系。这是原文关系还原，没有宣称真实控制关系恢复。

## 示例公式与可观测特征

资金熵定义为同一发送方、链、币种下接收方金额占比的 Shannon 熵（bit）。金额波动定义为同组逐笔金额的总体标准差除以均值。月内占比按导入时区日历月计算，先过滤截至时间；分母只包含可见记录，不声称已经取得全月流水。没有核验过的混币服务名单和覆盖范围时，混币率保持缺失。

四个权重公式按大纲配图实现条件计算：

| 流别 | 计算 | 必需补充的观测/定义 |
| --- | --- | --- |
| 资金 | 单笔金额 / 月度发送总额 × 时间异常因子 | 完整月度总额的口径及时间异常基准 |
| 货物/产业 | exp(-实际运输时长 / 最短路径运输时长) × 伪装程度 | 两项时长同单位；最短路径基准和伪装程度定义 |
| 信息 | 信息相似度 / (1 + 传播跳数) × 暗语强度 | 相似度算法、跳数与暗语尺度 |
| 人员 | 共同出现次数 / (1 + 关系路径长度) × 时间重叠因子 | 共现定义、路径基准及 n(时间重叠)函数 |

本工程约定相似度和伪装程度输入在 [0,1]，跳数、路径长度和次数为非负整数，时间因子和暗语强度非负；它们不是原材料已给定的训练校准参数。原材料没有定义 n()，因此不私自选择函数。缺少输入输出“未计算”，不填零或中性因子。权重不解释为违法概率，也没有接入现有 29 维分类器权重。
