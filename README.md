# 反电诈四流辅助研判系统 1.9.1

这是一个在自己电脑上运行的辅助分析程序。你把案件表格或文字资料导入后，可以查看资金、通信与 IP、人员活动、产业与货物流之间的关联，核对原始出处，并导出报告。

“四流”可以理解为四类相互对照的记录：

| 类别 | 常见资料 | 想回答的问题 |
| --- | --- | --- |
| 资金流 | 付款、收款、银行或钱包记录 | 钱从哪里来、经过哪些账户、流向哪里 |
| 信息流 | 通信、访问日志和 IP 地址记录 | 哪些账户、设备或主体在什么时间发生联系 |
| 人员流 | 人员活动、职责和明确关系记录 | 哪些人被材料提及，记录中有什么活动或关系 |
| 产业/货物流 | 订单、运输、物品或服务记录 | 付款是否与某个订单或交付记录存在来源明确的关联 |

这些问题能回答到什么程度，取决于你实际提供了什么资料。系统不会从一份文字简介中自动补全银行流水、IP 日志或真实物流。

**第一次使用，先按下面的启动和演示步骤操作即可，不需要先学会训练模型，也不需要把后面的命令全部执行一遍。** GitHub 网页负责存放代码和说明；真正的操作界面需要在电脑上打开。

> 随仓库提供的演示数据是虚构的，资金、人员和联合模型也是用合成数据训练的。系统能提供关联候选、统计和来源核对，真实案件识别准确率尚未验证。“候选”“待核验”和“材料不足”需要按字面理解。

## 一、已配置电脑怎么启动

这一节适用于原来已经运行过系统的电脑。**已经能正常启动，就不需要重新安装 Python 或重新创建环境。**

### 方法 A：双击启动

1. 打开 Windows 的“文件资源管理器”，就是平时打开文件夹的窗口。
2. 进入你原来使用的项目文件夹。原开发电脑上的位置是 `D:\Projects\FourFlowAnalysis`；这只是原电脑路径，不是其他电脑必须存在的地址。
3. 找到 **`启动系统.vbs`** 并双击。
4. 等待桌面窗口出现。右上角应显示版本 **1.9.1**。
5. 如果提示“工作区已打开”，返回已经打开的窗口即可。

双击后没有窗口时，按[常见问题](#faq)中的“启动没有反应”查看错误。

### 方法 B：在 PyCharm 中启动

PyCharm 是用来打开和运行 Python 项目的软件，系统本身不要求你必须使用它。

1. 打开 PyCharm，选择 **Open / 打开**，选整个项目文件夹，不要只打开 `fourflow` 子文件夹。
2. 打开设置，找到 **Python Interpreter / Python 解释器**；不同版本也可能放在 **Project Structure / 项目结构** 中。
3. 添加或选择一个**已有的本地解释器**，文件选当前项目里的 `.venv\Scripts\python.exe`。
4. 例如，原项目对应 `D:\Projects\FourFlowAnalysis\.venv\Scripts\python.exe`。项目位置不同，就选择实际项目下的同名文件。
5. 在左侧找到项目最外层的 `app.py`，右键选择 **Run 'app' / 运行**。
6. 第一次新建运行配置时，工作目录选项目最外层，即同时包含 `app.py` 和 `README.md` 的文件夹。

**成功标志：** 出现“反电诈四流辅助研判”的桌面窗口。只看到编辑器里的代码不算已经启动。退出时先等当前任务结束，再关闭系统窗口；用 PyCharm 启动时，也可在运行面板点击停止按钮。

菜单名称随 PyCharm 版本可能不同，选择已有环境的方法可查 [PyCharm 官方说明](https://www.jetbrains.com/help/pycharm/configuring-python-interpreter.html)。

## 二、在另一台电脑从头安装

“重建环境”的意思是：在新电脑上重新准备 Python 和项目需要的配套库。仓库有代码和小型模型，但没有原电脑的 `.venv` 环境，所以**仅下载文件后直接双击启动脚本，通常还不能运行**。

本节只需首次安装时做一次；安装完成后，日常按上一节启动即可。

### 第 1 步：确认准备条件

| 项目 | 需要知道的内容 |
| --- | --- |
| 操作系统 | 按 Windows 64 位编写和验证操作步骤；其他系统未做完整桌面验收 |
| Python | 原机使用 Python 3.13.5、64 位；新机可先选仍受支持的 Python 3.13 系列普通 64 位版本，不选实验性的自由线程版本 |
| 显卡 | 原机用 CPU（电脑处理器）运行，可以先做表格、文字和小规模模型演示，不要求先准备独立显卡 |
| 文件位置 | 以下统一示范放在 D 盘；实际路径不同，命令中的路径也要一起修改 |
| 网络 | 下载源码、安装配套库和准备语音模型时需要网络；已准备好的资料分析在本机执行 |
| PyCharm / Git | 普通使用者可不安装，用下载 ZIP 和 PowerShell 的方式也能完成 |

本项目已在原机既有环境中完成运行和搬移检查，**尚未在完全空白的新电脑上完成整套安装验收**。下面提供安装和检查方法，不把它写成所有新电脑配置都已实测通过。

### 第 2 步：下载完整项目并解压到 D 盘

1. 打开[项目仓库首页](https://github.com/xiaoxiaofutongxue/anti-telecom-fraud-model)。
2. 在文件列表上方点击绿色 **Code** 按钮，再选 **Download ZIP**。
3. 下载完成后右键 ZIP 文件，选择“全部解压缩”。**不要直接在压缩包内运行程序。**
4. 在 D 盘建立 `Projects` 文件夹，把解压后的项目文件夹放进去。
5. 以下假设把文件夹改名为 `anti-telecom-fraud-model`，最终位置为 `D:\Projects\anti-telecom-fraud-model`。如果已有同名项目，另建目录，不覆盖旧项目和资料。
6. 打开后应该直接看到 `app.py`、`cli.py`、`README.md`、`requirements-lock.txt`、`fourflow` 和 `data`。如果只看到另一个文件夹，再进入一层，直到看见这些文件。

不需要逐个下载 Python 文件。完整 ZIP 才同时包含程序、演示数据、模板和三份 Word。[GitHub 官方下载说明](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)也介绍了这个操作。

### 第 3 步：安装或确认 Python

Python 是执行程序的运行工具。已经安装并能使用 Python 3.13 的，可以先检查，不必重复安装。

1. 从 [Python 官方 Windows 下载页](https://www.python.org/downloads/windows/)获取 Python 3.13 系列普通 **Windows installer (64-bit)**。不要用源代码包或嵌入式包代替普通安装程序。
2. 使用传统安装程序时，可勾选 **Add python.exe to PATH**，保留 `pip` 和 `tcl/tk` 组件。前者用于安装配套库，后者用于显示本项目桌面窗口。
3. 想把 Python 本体也装到 D 盘，可选自定义安装，将目录设为例如 `D:\Software\Python313`。已经有可用 Python 的，不用为了路径位置卸载重装。
4. 安装完成后重新打开 PowerShell，让它读到新的安装信息。

原机 3.13.5 是验证时的版本，不是“越旧越好”的要求；更换小版本后仍需自检。安装选项可查 [Python 官方 Windows 使用说明](https://docs.python.org/3.13/using/windows.html)。

### 第 4 步：打开 PowerShell，进入项目目录

PowerShell 是 Windows 输入命令的窗口。按 Windows 键，输入 `PowerShell` 并打开，一般不需要管理员权限。也可用 PyCharm 底部 **Terminal / 终端**，但要确认它是 PowerShell。

**代码框里的命令一次复制一行，粘贴后按回车，等执行结束再输入下一条。不要复制解释文字，也不要输入到 Python 的 `>>>` 窗口。**

先进入解压后的项目：

```powershell
Set-Location "D:\Projects\anti-telecom-fraud-model"
```

这只是告诉 PowerShell“接下来在这个文件夹操作”，不会安装东西。

再查看文件列表：

```powershell
Get-ChildItem
```

**成功标志：** 列表中能看到 `app.py` 和 `requirements-lock.txt`。看不到就先找对目录，不要继续安装。

### 第 5 步：确认 Python，创建项目自己的环境

先检查 Python 3.13：

```powershell
py -3.13 --version
```

**成功标志：** 显示 `Python 3.13.x`，末位随安装版本变化。

然后创建项目环境：

```powershell
py -3.13 -m venv .venv
```

这会在当前项目中建立 `.venv`。可以把它理解成“项目专用的工具箱”，使它的配套库不与其他项目混在一起。执行时可能没有文字输出；等回到可输入命令的状态，再检查：

```powershell
.\.venv\Scripts\python.exe --version
```

**成功标志：** 仍显示 Python 3.13.x，且项目中已有 `.venv\Scripts\python.exe`。

如果 `py` 找不到，但 `python --version` 已显示正确的 3.13.x，可将本步前两条中的 `py -3.13` 换成 `python`。两者都找不到时，先修复 Python 安装，不要跳过本步。

### 第 6 步：安装配套库

`requirements-lock.txt` 是“配套库及版本清单”。读 Excel、计算和识别文字等功能都依赖相应库；安装 Python 本身不会自动装好它们。

先把本次终端的安装缓存放到 D 盘：

```powershell
$env:PIP_CACHE_DIR = "D:\Projects\pip-cache"
```

再安装清单中的库：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

第一次会下载很多文件，包括 CPU 版计算库。等待命令结束；耗时取决于网络，不要因短时间没有新文字就反复启动安装。

**成功标志：** 安装正常结束，没有安装失败的 `ERROR`。`Requirement already satisfied` 表示“已经安装过这个库”，可以继续。

接着检查库之间是否冲突：

```powershell
.\.venv\Scripts\python.exe -m pip check
```

**成功标志：** 显示 `No broken requirements found.`，即“没有发现依赖冲突”。安装报错时先看[常见问题](#faq)，不要随意改版本号隐藏问题。

这里始终直接使用 `.venv` 内的 Python，不需要额外执行“激活环境”脚本，也不用为此修改 PowerShell 执行策略。

### 第 7 步：自检，再启动界面

先检查库、随包模型和默认样例：

```powershell
.\.venv\Scripts\python.exe cli.py preflight
```

`checks` 表示“检查清单”，`ready` 表示“本轮检查是否通过”。`"ready": true` 说明这些软件和文件检查通过，**不代表真实识别效果通过验证**。它也不确认所有媒体模型，语音功能还要按下一节准备。

然后启动：

```powershell
.\.venv\Scripts\python.exe app.py
```

**成功标志：** 桌面窗口出现，右上角显示 1.9.1。界面运行时，这个终端暂时不能继续输入是正常的；关闭界面后会返回命令行。

以后双击项目里的 `启动系统.vbs`，或在 PyCharm 中选择本项目 `.venv\Scripts\python.exe` 再运行 `app.py` 即可。不用每天重新安装。

<a id="speech-model"></a>
## 三、只有需要音频转写时，再准备语音模型

处理 Excel、CSV 和普通文字资料可以先跳过本节。

语音模型负责把录音转成文字。它体积较大，GitHub 源码仓库没有放入，与仓库里已有的小型资金、人员及联合模型不是同一组文件。

完成依赖安装后，在项目目录执行：

```powershell
.\.venv\Scripts\python.exe tools/prepare_local_models.py
```

这个步骤会联网下载公开 Whisper base 语音权重，放在项目内的 `runtime\models\whisper_base`，相关下载缓存也设在项目内。成功后显示“离线语音权重可用”及路径。

下载失败时，文字和表格流程仍可先用；录音和视频声音需要等语音模型准备成功。正常识别阶段读取本地材料和模型，不需要把案件录音上传到在线识别服务。语音识别使用已有公开基础模型，不是本项目从零训练出的语音基础模型。

## 四、先做一次演示

演示的目的是确认“导入 → 查看 → 找原文 → 核验 → 导出”跑得通。

1. 启动系统，进入左侧 **案件文本研判**。
2. 点击 **合成四流演示**，等底部状态提示完成。它建立新的资料批次，不改写旧批次。
3. 打开 **四流关联与产业溯源**，找演示订单 `DEMO-O1`，查看资金、通信/IP、人员与产业记录的连接依据。
4. 打开 **资料检索与原行**，选一条记录，查看文字、文件和行号。“原行”就是原文件中实际记录这段内容的位置。
5. 点击 **打开研判报告**，浏览器应打开本机生成的报告。浏览器在这里用于阅读本地文件，不是在把案件上传到 GitHub。
6. 若练习填写意见，填写核验人和依据，保存后再点 **更新并导出报告**，然后重新打开报告确认意见已出现。

演示还有故意设置的反例：相同金额、共同 IP 不应直接当作同一订单或同一人。**图谱连线表示系统找到了某种关联依据；打开来源才能知道它依据什么。**

<a id="import-documents"></a>
## 五、导入工作簿或文字资料

### 哪类文件先走这个入口

如果 Excel 主要是案件描述、人物关系、资产清单、支付陈述和四流分析文字，先用本节。你之前提供的三份案件分析工作簿属于这一类。

支持 `.xlsx`、`.csv`、`.tsv`、`.docx`、`.txt`、`.md`，也可以粘贴文字。旧 `.xls` 先用 Excel 另存为 `.xlsx`。图片、扫描 PDF、音频和视频走[原始材料识别](#other-modules)，不要在这里当工作簿导入。

### 从导入到拿到报告

1. 点击顶部 **案件文本导入**，或进入 **案件文本研判** 后点 **导入案件文本并研判**。
2. 选择一个文件后点“打开”，就能单独分析。想一次处理多份，可按住 Ctrl 选择多个。
3. 等状态栏提示完成。系统保留原件副本、读取文字和表格，并生成初版报告。
4. 在 **当前资料** 下拉框中选要看的文件；多文件批次在这里逐份切换。
5. 按下表查看结果，再回到原行核对重要内容。

| 页面 | 解决什么问题 | 重点查看 |
| --- | --- | --- |
| 四流研判摘要 | 了解这份资料有什么 | 来源、内容行、路径摘录和主要缺口 |
| 需求输出与核验 | 查看需求输出能提供到什么程度 | 已有内容、出处、还缺的材料 |
| 结构还原与核算 | 查看明示关系方向和支付明细 | 原文是否明确、金额类型、日期与计算条件 |
| 四流关联与产业溯源 | 查看资金、信息/IP、人员与产业记录如何关联 | 订单或共同标识、时间条件、原行和缺口 |
| 资料检索与原行 | 找回结论来自哪里 | 原文、工作表、行号、核验状态 |
| 主体与资产提及 | 查看人物称谓、账户和资产 | 同名、匿名编号、掩码是否有身份歧义 |
| 金额与时间口径 | 区分哪些数字可以怎样计算 | 交易、余额、费用、汇总、约数和未知日期 |

6. 在 **资料检索与原行** 选中记录，点 **打开原件**，按文件、工作表和行号检查。
7. 选择实际核验状态，填写核验人和依据/备注，点 **保存本条核验**。尚未核对原材料就不要写成“已核实线索”。
8. 点 **更新并导出报告**，等完成，再点 **打开研判报告**。保存意见后需重新导出，旧报告不会自动改写。

### 怎样理解输出

- 可以一次一份，也可以一次多份；新导入建立新批次，旧资料可用 **打开已接入资料** 恢复。
- 不同文件默认各自分析，不会凭同名人员或相同编号自动合案。需要多张业务表按同案共同建图时，使用下一节。
- 有明确字段才做对应计算；只有文字陈述时，保留为来源陈述，不自动变成逐笔交易。
- 缺 IP、时间、订单或身份依据时列出缺口，不会自动补出真实位置、完整资金链和已确认产业用途。
- “列示项目合计”不是全案损失；余额、行业数字、费用、受害者汇总不能随意相加为转账总额。

三个案件原件没有放在 GitHub。换电脑后请从你保存的原件重新选择，仓库演示文件不能替代它们。

## 六、导入固定列名的业务表

如果是“一行一笔转账”“一行一次 IP 访问”“一行一条通信”，用顶部 **CSV/Excel接入**。它把你原表的列对应到系统字段，例如原表“付款账户”对应资金表的 `from_id`；这叫“列映射”，不要求逐条重写数据。

### 具体步骤

1. 点 **CSV/Excel接入**。第一次可先点向导里的 **合成演示**，看懂预览和列对应。
2. 导入自己的文件时点 **选择CSV/Excel**，选 `.csv`、`.tsv` 或 `.xlsx`；Excel 再选具体工作表。
3. 填写默认案件编号、标题、地区和案型。实际业务资料的来源选 `real`，虚构演示选 `synthetic`。来源标记本身不证明内容已经核实。
4. 选择 **接入类型**，例如资金记录、IP 访问、通信、主体或产业记录，不把日志当资金表。
5. 点 **预览/更新列对应**，对照右侧前 12 行，核对左侧字段。自动建议只是建议，付款/收款方向、金额、币种和时间尤其要检查。
6. 缺列时查[数据字典](docs/数据字典.md)和原件。“默认值”用于未映射字段，不能为了通过校验编造金额、时间、主体或标签。账户、订单等编号尽量保存为文本，避免丢失前导零或变成科学计数法。
7. 点 **将当前表加入队列**。队列就是“准备一起接入的表清单”。还有其他文件或工作表，就继续选择、预览并加入。
8. 同一案件的资金、通信、IP、人员和物流表使用一致的案件编号，以及含义一致的主体、账户或订单编号。不同案件使用不同编号，不能只靠名称相同拼接。
9. 点 **生成并载入新数据集**。数据集就是这批统一格式的表。成功后回到工作台；若显示错误，先核对和修正，不把接入失败当成“没有风险”。
10. 进入 **实证与运维 → 接入与全流程**，先按需点 **环境自检**，再点 **一键本地全流程**，结束后点 **打开输出**。

### 你关心的功能在哪里

| 需求 | 操作 | 结果 |
| --- | --- | --- |
| 数据清洗 | **清洗与质量 → 选择原始数据并清洗到新目录**，选择已符合系统结构的数据目录及新的空输出目录 | 规范化结果、问题隔离及 `cleaning_report.json`，原目录不改写 |
| 资金分析 | 查看 **工作台、模式核验、四流图谱**，或运行一键全流程 | 分币种统计、拆分/归集等提示、带来源的路径 |
| 信息与 IP | 查看 **IP与产业溯源** | 格式、共享/变化提示和来源；同 IP 不直接等于同一人 |
| 人员分析 | **主体与身份**、**人员·因果·材料 → 人员角色与层级** | 身份关联与人工核验；模型适用时才提供分类候选 |
| 产业/货物流 | **IP与产业溯源**，检查订单和证据 | 付款、产业订单与其他流的关联候选、待补材料 |
| 输出 | 顶部 **导出分析报告**，或全流程后的 **打开输出** | 网页、图谱、表格和可打包的结果 |

**清洗页选择的是系统格式的数据目录，不是任意一个 Excel。** 任意 CSV/Excel 先走接入向导；接入未通过时先修正列对应或原数据。案件文字批次也不能直接当作已整理好的逐笔流水数据集。

真实数据没有适配且验证过的模型时，仍可做统计、图谱、IP/订单关联和人工核验；自带合成模型会拒绝给真实案件评分。这不等于导入失败，不能把真实数据改成 `synthetic` 绕过。

### 不同文件怎么用

- **HTML**：双击用浏览器阅读。文字/全流程报告从 `index.html` 开始，常规结构化导出从 `report.html` 开始。
- **CSV**：用 Excel 看明细。文字报告中，`statement_payments.csv` 是明示付款，`industry_candidates.csv` 是产业候选，`reviews.csv` 是核验意见；不同入口和资料可能提供不同文件。
- **JSON**：完整性较高的机器可读结果，供程序和追溯使用；普通阅读不用先看它。
- **SVG**：可放大的图谱，适合查看细节或插入报告。
- **ZIP**：整组结果的压缩包。案件文本及常规报告旁边会生成对应 ZIP，便于完整保存和传递。

需要在另一台电脑阅读完整报告时，优先传对应 ZIP，解压后打开首页。**只复制一个 HTML 可能丢图、原件和原行链接。** 结果中可能包含导入原件和核验信息，按实际资料的保管要求处理。

### 保留工作进度和备份

核验意见在本机数据库，GitHub 不会自动备份它。进入 **实证与运维 → 备份与恢复**，可以创建当前工作区备份、校验备份、恢复到新的空目录。

备份包括当前数据和相关原件、核验库、已选模型等，**不是全部历史文件总备份**；外置旧报告、其他数据集也需单独保存。备份未加密，不当作公开上传文件。

## 九、常见问题

### 1. 双击提示 `Python environment missing`

即“项目里找不到 `.venv` 中的 Python”。按[首次安装](#install-new)创建环境并安装依赖。新下载的文件不会自带原电脑环境，直接复制其他电脑的 `.venv` 也不可靠。

### 2. 双击没反应，或者窗口一闪而过

在 PowerShell 进入项目目录后执行下面的命令，让错误留在终端：

```powershell
.\.venv\Scripts\python.exe app.py
```

也可查看 `runtime\application.log`。反馈时提供完整错误文字、命令、项目路径和出错步骤。提示已有窗口时，先返回已打开窗口。

### 3. 提示 `py` 或 `python` 不是可识别的命令

终端没找到 Python。先关闭终端重开；仍不行则确认 Python 安装、启动器或路径配置。知道实际安装位置时可用完整路径，例如：

```powershell
& "D:\Software\Python313\python.exe" -m venv .venv
```

路径必须换成实际存在的文件。`&` 是 PowerShell 执行带引号路径的符号。

### 4. 提示找不到 `app.py` 或 `requirements-lock.txt`

一般是当前目录不对，或没有完整解压。用 `Get-ChildItem` 看列表，定位到同时包含二者的目录再执行。

### 5. 安装报错，出现 `No matching distribution found`

即某库的指定版本没找到适合当前环境的安装文件。检查是否 Python 3.13 普通 64 位、网络是否失败、具体哪个库或版本报错。

锁定清单来自原机环境，不同机器、Python 版本和下载源未逐一验证。保留完整错误排查，不随意删除库或改成未知版本后宣称成功。

### 6. PyCharm 报 `ModuleNotFoundError`

即当前 Python 找不到某个库。核对解释器是不是**当前项目**的 `.venv\Scripts\python.exe`，再按安装步骤补齐库。电脑别的 Python 装过同名库，不代表当前项目能用。

### 7. 提示语音模型没准备好

依赖库与语音模型是两回事，按[第三节](#speech-model)执行下载脚本。成功前先用表格和文字；环境自检通过不等于所有媒体权重已就绪。

### 8. 导入成功，某板块却没结果

案件文本页面使用文字批次，其他流水页面使用结构化数据集，不自动互相替换。先确认入口，再看资料是否有该功能需要的字段。

没有明确时间与主体引用的 IP 记录，就不能做对应的时间窗关联；没有订单或运单依据，不能凭金额接近补货物流。“资料未提供”不等于“行为不存在”。

### 9. 导入真实文件后暂不评分

自带模型来自合成数据，分数不能冒充真实识别结果。仍可查看清洗质量、金额、来源、图谱、IP/订单候选和报告。验证真实识别需要核实标签、任务定义和独立外部评测。

### 10. 保存意见后报告没变化

点 **更新并导出报告**，等完成后重新 **打开研判报告**。不要继续看之前打开的旧文件，实际位置以本次完成提示为准。

### 11. 换电脑后没有原来的案件和意见

仓库没有真实原件、私人批次、核验库和运行报告。需从保管的原件重新导入，或用私有工作区备份恢复；源码 ZIP 不是业务资料备份。

### 12. 为什么还有 1.5、1.8 文档

它们是升级历史，当前软件是 **1.9.1**。旧测试计数和合成示例仅对应当时验证，不是当前真实识别准确率。
